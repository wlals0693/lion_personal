# 로컬 GPU 사진 등록 연결·측정

2026-11-10 01:01 KST. `lion_personal`에서 실제 Next.js 프로덕션 서버와 Chromium Headless 158, RTX 3070 Ti를 연결해 확인했다. 배포는 수행하지 않았다.

## 구현

업로드 버튼 → 원본 파일 선택·미리보기 → `POST /api/garments/analyze` → 로컬 Python 이미지 게이트웨이 → 상주 llama.cpp CUDA 모델 → 옷 종류·소매 입력란 자동 반영. 예측값은 사용자 수정과 기존 브라우저 저장을 지원하며, 상세·수정 화면과 새로고침 후에도 유지된다.

직접 올린 사진은 실제 모델을 사용하고, 제공된 예시 사진만 체험용 응답을 유지한다. 서버 연결 실패 시 예시 예측으로 대체하지 않는다. 색상·스타일은 평가하지 않은 항목이므로 사용자가 선택한다.

모델은 앞선 비교에서 사용한 Qwen3-VL 4B GGUF Q4_K_M, F16 비전 프로젝터, llama.cpp b12224 CUDA 12.4다. 원본의 EXIF 보정·RGB 변환·최대 768px LANCZOS, 같은 프롬프트, temperature=0, seed=42, 최대 240토큰, 배치/마이크로배치 128, 모델·비전 CUDA0, 프롬프트 캐시 비활성화를 유지했다. 휴대폰 JPEG에 포함된 MPO 컨테이너도 첫 프레임을 처리한다. 사진은 파일로 저장하지 않고 메모리에서 분석한다. 옷장 저장 시에만 기존 localStorage 저장을 수행한다.

GPU 서버는 `127.0.0.1:8092`, 모델은 `127.0.0.1:8091`, 검증 웹은 `127.0.0.1:3000`을 사용했다. API는 원본 파일명·정답을 모델에 전달하지 않는다.

## 실제 화면 표시 시간

| 사진 ID   | 업로드 클릭 → 화면 | 파일 선택 → 화면 | 서버 전처리·추론 |
| --------- | -----------------: | ---------------: | ---------------: |
| photo_000 |            1.393초 |          1.305초 |          1.180초 |
| photo_005 |            1.547초 |          1.207초 |          1.092초 |
| photo_020 |            0.862초 |          0.852초 |          0.796초 |
| photo_028 |            0.862초 |          0.846초 |          0.794초 |
| photo_042 |            0.913초 |          0.903초 |          0.852초 |
| 평균      |        **1.115초** |      **1.022초** |      **0.943초** |

원문은 [GPU_REGISTRATION_TIMING.json](GPU_REGISTRATION_TIMING.json)에 보존했다. photo_000은 모델 서비스를 시작한 뒤 첫 사진 요청이고, 나머지는 같은 상주 모델을 사용했다. 별도의 이미지 워밍업을 수행하지 않았다. 서버 시작·가중치 로딩은 업로드 전에 끝나므로 위 시간에 포함되지 않는다.

클릭 처리기의 `performance.now()`부터 종류·소매가 채워진 React 커밋 이후 두 번째 `requestAnimationFrame`까지 측정한다. 브라우저에 `performance.measure('wardrobe-upload-to-visible')`도 남긴다. 실제 물리 화면의 광학적 표시를 측정한 값이 아니라 브라우저 페인트 경계를 이용한 지표다. `서버 전처리·추론`은 Python 이미지 전처리·모델 HTTP 요청·응답 파싱을 포함하며 순수 생성 시간만을 뜻하지 않는다.

자동화가 업로드 버튼을 누르고 파일 선택창에 즉시 파일을 전달했다. 사람이 파일을 찾는 시간은 재현하지 않았으며 실제 사용 시 클릭부터의 시간은 그만큼 늘어난다. 표본 5장의 단회 진단으로 모든 업로드의 지연 분포나 네트워크 환경을 대표하지 않는다. 기존 0.84초/장은 모델 실험 시간이며 이 브라우저 측정과 직접 같은 값이 아니다.

## 검증 결과

- 실제 사진 5장 자동 입력 성공. photo_000은 셔츠·반팔, photo_005는 스포츠 저지·반팔, photo_020은 민소매, photo_028은 티셔츠·반팔, photo_042는 티셔츠·긴팔로 표시됐다. 이는 모델 출력이며 종류 정답을 모두 맞혔다는 의미는 아니다.
- 첫 사진의 소매를 긴팔로 수정·저장한 뒤 새로고침 및 수정 화면에서 값 유지 확인.
- 지원하지 않는 MIME 입력은 실제 API 400, 손상 JPEG는 실제 GPU 게이트웨이 경유 422 확인.
- 브라우저에서 503 오류를 주입해 가짜 결과를 표시하지 않는지 확인한 뒤 주입을 해제하고 같은 파일로 실제 모델 재시도 성공.
- GPU 서비스를 실제로 종료한 뒤 정상 JPEG를 웹 API에 보내 503을 반환하는지 추가 확인했다. 다른 출처의 Origin 요청은 403으로 거부했다.
- 데스크톱 1280×900, 모바일 뷰포트 390×844에서 입력란 확인. 스크린샷은 로컬 `test-results/gpu-registration-desktop.png`, `test-results/gpu-registration-mobile.png`에 저장했으며 사진이 포함되어 Git에서 제외했다.
- 초기 스트리밍 화면에서 저장소 복원과 hydration이 충돌하던 문제를 보완한 최종 실행에서는 브라우저 런타임 오류가 없었다.
- `npm run typecheck`, `npm run build`, 기존 회귀 테스트 12개 및 실제 브라우저 검증 통과.

실행·재현 절차는 [README](../README.md#로컬-gpu-사진-등록)를 따른다. 코디 추천·구매분석·인증·날씨는 기존 체험 기능이다. 웹만 외부에 배포하면 이 PC의 loopback GPU 서버에는 연결되지 않는다.
