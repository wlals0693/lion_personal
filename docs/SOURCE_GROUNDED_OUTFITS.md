# 자료를 연결하는 코디 추천 V3 — 2026-11-24

## 구현 상태와 주장 범위

웹의 새 추천 요청은 `outfit-v3-sources`를 사용한다. 기존 V1/V2는 비교용으로 보존했다.
이는 **출처가 있는 디자인 기준을 사진 관찰에 적용하는 실험**이며 전문가 코디 정답이나 논문 모델의 재현이 아니다.
학습 모델·파라미터·패션 정확도가 새로 검증된 것은 아니다. Qwen 모델은 기존 것을 재사용한다.

현재 확인한 것은 근거 연결의 구조적 검사와 웹 통합이다. GPU 실제 추론, 새 JSON 스키마 준수율,
실제 사진 관찰 정확도, 추천 수용률, 설명 충실도 및 속도는 **미측정**이다.
로컬 테스트의 모델 응답은 명시적으로 만든 fixture이며 실제 패션 판단 결과로 집계하지 않는다.

## 출처와 적용 범위

| 자료 | 사용한 부분 | 허용하는 해석 | 허용하지 않는 주장 |
|---|---|---|---|
| [The Museum at FIT: Elements and Principles of Fashion Design](https://www.fitnyc.edu/museum/documents/elements-and-principles-of-fashion-design.pdf) | PDF p.3 색의 명도·강도, p.4 강조·반복 | 눈에 띄는 요소와 반복을 관찰하는 기준 | 같은 색이면 정답, 패턴은 하나만 허용 |
| [Utah State University Extension: Design Principles for Clothing and Textiles](https://extension.usu.edu/research/principles-of-design) | Emphasis / Rhythm / Harmony; 2016년 peer-reviewed fact sheet | 앙상블 관계를 판단하는 교육 원리; 주관성 인정 | 특정 코디의 과학적 성공 확률 |
| [OutfitTransformer](https://arxiv.org/abs/2204.04812) | §3.1, §4.5 | 전체 조합 단위 평가와 사람 평가를 설계하는 참고 | Qwen이 OutfitTransformer와 같은 성능·학습을 수행 |
| [PFE](https://arxiv.org/abs/2312.11554) | §3의 특징 추출/설명 분리, §4 사람 평가 | 관찰과 판단을 분리하는 설계 참고 | PFE 데이터로 학습했거나 설명 충실도가 입증됨 |

교육 원리의 요약과 서비스 적용 조건은 `scripts/outfit_knowledge.json`에서 관리한다.
`principle`은 제한적 요약이며 `application`/`limits`는 서비스 운영 해석이다. 논문은 코디 규칙집이 아니다.
두 교육 자료의 강조·반복·전체 조화 기준만 초기 적용한다. 실제 착용 비율·체형·원단 조성은 사용하지 않는다.
격식·날씨·개인 취향의 전문가 근거는 아직 확보되지 않았으므로 해당 상황을 단정하지 않는다.

## 실제 처리

1. 기존과 같은 768×768 번호 사진에서 Qwen이 의류별 관찰만 추출한다. 추천 판단은 하지 않는다.
2. 모호한 관찰과 일부 사진으로 판단할 수 없는 속성을 제외한다. 이는 완전한 사실 검증이 아니다.
3. 적어도 두 의류에 관찰된 특징 축을 기준으로, 작은 기준 목록에서 관련 항목을 선택한다.
   단순하고 추적 가능한 검색이며 벡터 DB나 실시간 웹 검색은 사용하지 않는다.
4. 두 번째 Qwen 호출은 사진 없이 관찰·선택된 기준·상황으로 조합을 판단한다.
   이유마다 `criterionId`, `evidenceIds`, `effect`, `application`을 반환한다.
5. 서버가 기준·관찰·의류 ID 관계를 검사하고 등록된 출처만 붙인다. 모델 생성 URL은 사용하지 않는다.
6. 추천은 모든 의류가 이유의 관찰에 참여해야 한다. 근거 부족·불명확한 관계·등록 정보와 사진 충돌은 보류한다.
   불일치 이유가 없는 거절도 보류한다. 추천 개수를 강제로 채우지 않는다.
7. 화면은 관찰 / AI 적용 해석 / 자료의 일반 원리 / 출처를 구분한다. 접힌 ‘판단에 사용한 자료’에서 확인한다.

이 검사로 존재하지 않는 인용과 끊어진 연결을 차단할 수 있지만, 잘못된 시각 관찰이나 자료를 잘못 적용한
문장까지 자동 판별하지는 못한다. 출처가 붙었다고 그 코디가 입증된 것은 아니다.
입력 사진의 배경·조명 영향도 남는다. 의류가 적으면 추천이 과도하게 보류될 가능성도 측정해야 한다.

## 실행

기존 모델 환경이 준비된 데스크탑에서 저장소의 최신 코드를 받고 **GPU 프로세스도 재시작**한다.

```powershell
npm run demo
```

실제 서비스의 코디 추천 버튼으로 V3를 요청한다. 기존 저장된 V2 결과는 V3로 재표시하지 않으며 새로 평가해야 한다.
이전 GPU 서버가 V3를 지원하지 않으면 오류로 처리하고 조용히 V2로 대체하지 않는다.
추가 모델 다운로드는 없다. 사진 관찰 1회 + 텍스트 판단 1회로 후보당 2회 호출하므로 기존보다 비용·지연이 늘 수 있다.
두 번째 호출에는 비전 인코딩이 없지만 전체 속도 개선을 주장할 수는 없다. 기존 웹 시간 제한은 유지한다.

## 고정 입력 비교 실험

노트북에서도 GPU 없이 입력만 준비할 수 있다. 폴더 카테고리는 실험 구성에만 쓰고 상품명·파일명은 모델에 보내지 않는다.
사진은 각 폴더 최대 3장, 최대 6개 조합이다. 기존 사진은 개발용 파일럿이며 새로운 독립 검증셋이 아니다.
아래 `python`은 Pillow가 있는 Python 환경이어야 한다. 출력 폴더는 새 이름이어야 한다.

```powershell
python scripts/compare-outfit-sources.py --photos "사진폴더" --prepare-only --out test-results/source-input
```

GPU가 준비되면 서버 실행 상태에서 다른 터미널로:

```powershell
python scripts/compare-outfit-sources.py --payload test-results/source-input/input.json --out test-results/source-comparison-01
```

동일 사진·상황·조합으로 V2/V3를 실행하고 원본 응답, 요청 해시, 모델명, 실행 순서와 시간을 기록한다.
실행 순서는 seed로 정하며 워밍업·실행 순서 효과를 없앤 정밀 벤치마크는 아니다.
`blind-review.html`은 동일 사진과 두 방법의 설명을 나란히 보여준다. `blind-review.csv`는 방법명을 A/B로 가린 평가표다. 평가자에게 HTML과 JPEG 및 CSV를 함께 제공하고
`private-key.json`은 공개하지 않는다. 문체로 방법을 유추할 수 있어 완전한 맹검은 아니다.
개별 사진과 모델 원본 응답은 개인정보 자료이므로 출력은 기본적으로 Git에서 제외된 test-results에 둔다.

### 사람이 채울 항목

- `raterId`, `raterRole`: 전문 교육/실무 경험과 일반 사용자 여부를 구분한다.
- `wearable_1to5`: 명시한 상황에서 입을 만한지 1(분명히 부적절)~5(적절), 판단 불가이면 빈칸과 사유를 남긴다.
- `factsSupported_yes_no_uncertain`: 설명에 등장한 의류·색·패턴이 사진과 맞는가.
- `explanationSupported_yes_no_uncertain`: 관찰에서 설명이 타당하게 이어지는가.
- `notes`: 존재하지 않는 속성, 억지 관계, 상황을 가정한 판단 등을 기록한다.

출처의 원문이 적용을 뒷받침하는지는 별도의 출처 검토자가 원본 trace와 자료를 함께 보고 확인해야 한다.
평가표만으로 자료 충실도를 계산하면 안 된다. AI 자신을 전문가 정답 작성자로 사용하지 않는다.
추천된 결과만 평가하지 말고 보류/거절도 평가해 과도한 기권을 함께 확인한다.

개발 사진으로 기준을 수정한 후에는 **새 의류 단위로 분리한 평가셋**을 모으고 기준/프롬프트 버전을 먼저 동결한다.
최소 2명의 독립 평가자는 운영 제안이며 논문이 정한 보편적인 최소 인원이 아니다.
방법별 사진 오류율, 설명 오류율, 추천 수용률, 보류율, 지연과 평가자 간 의견 차이를 함께 보고한다.
결과를 보기 전에 성공 기준을 정하고 동일 조합의 쌍별 비교를 수행한다. 소수 파일럿의 차이를 일반적 성능으로 확장하지 않는다.
