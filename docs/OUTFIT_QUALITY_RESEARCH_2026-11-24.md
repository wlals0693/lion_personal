# 코디 추천·설명 품질: 구현 감사와 연구 근거

확인일: 2026-11-24. 로컬 코드 기준: 063e41e. 사용자 시연 화면, 현재 코드, 기존 학습 보고서와 아래 원문을 대조했다. 데탑의 최신 런타임·요청 로그는 직접 확인하지 않았다. 새 GPU 실험이나 모델 변경은 하지 않았다.

## 판단

현재 결과는 일부 무난한 조합을 제안할 수 있는 데모다. 사용자가 매번 납득할 만한 추천과 설명이라는 제품 품질은 아직 확보되지 않았다. 화면에 보인 문제는 취향 차이와 분리해 다뤄야 한다. 없는 소재·허리 높이의 단정, 같은 옷의 속성 혼동, 비슷한 조건에 상반된 이유를 붙이는 현상은 사실성·일관성 문제다. 특정 코디가 모든 사람에게 나쁘다는 뜻은 아니다.

기술 방향에는 연구 근거가 있지만, 현재 웹이 해당 연구의 학습 결과를 사용한다는 뜻은 아니다. 코디 구성 데이터로 궁합을 학습하는 것과 범용 VLM에 코디 사진을 평가시키는 것을 구분해야 한다.

## 1. 실제 웹이 수행하는 일

| 단계 | 실제 구현 | 확보되지 않은 것 |
|---|---|---|
| 후보 생성 | lib/outfit-evaluation.ts의 outfitCandidates. 카테고리·고정·제외에 따라 최대 6개를 순회 생성 | 패션 적합도로 후보를 찾아오는 검색 |
| 입력 | 사진을 개별 최대 360×340으로 축소하고 768×768 번호표에 배치 | 원본 디테일 보존 효과 검증 |
| 평가 | Qwen3-VL 4B Q4_K_M, 공통 프롬프트, 상황, JSON schema, temp0/seed42 | 전문가 기준 학습·기준 예시 검색·Pool32 호출 |
| 정렬 | 상황 부적합을 뒤로, 나머지는 시각적 3등급. 동률은 후보 순서 유지 | 동급 후보 사이의 실제 우열 판단 |
| 설명 | Qwen이 같은 요청에서 이유 문장 생성 | 문장의 사실성·판정 충실도 검증 |
| 화면 | 평가한 6개를 모두 추천 번호로 표시 | 보류/부적합 후보를 추천에서 제외하는 정책 |

근거 파일: lib/outfit-evaluation.ts, scripts/outfit_evaluation.py, scripts/outfit_prompt.txt, app/api/outfits/evaluate/route.ts, components/ai-outfits.tsx.

등록한 의류의 세부 종류·색상·수정한 속성은 현재 코디 Qwen 요청에 전달되지 않는다. Next는 category를 구성 검증에 사용하고, Python에는 ID와 사진을 전달한다. Qwen은 사진을 다시 해석한다. 따라서 등록 화면에서 맞춘 명칭과 코디 설명이 달라질 수 있다. 이 연결을 보완할 때도 AI 추정 속성을 확정 정답으로 전달해서는 안 된다.

현재 프롬프트에는 이미 대비가 항상 나쁜 것은 아니라는 지시, 허리 높이·입었을 때의 핏·소재 성분 추정 금지가 있다. 사용자 화면은 이 금지에도 과잉 추정이 남음을 보여준다. JSON schema는 형식 검증이지 내용 검증이 아니다. 금지 문구 추가만으로 해결됐다고 보고할 수 없다.

review는 현재 '눈에 띄는 충돌'과 '근거 부족'을 합친 값이다. 둘은 제품에서 다른 상태다. 충돌을 감지한 것인지 사진에서 판단하지 못한 것인지 구분할 필요가 있다. 또한 suitable과 uncertain은 현재 정렬에서 별도 우선순위를 갖지 않는다.

## 2. 기존 자료가 뒷받침하는 범위

### ECCV 2018: Type-Aware Embeddings

[원문](https://arxiv.org/html/1803.09196), [저자 코드](https://github.com/mvasil/fashion-compatibility).

같은 종류 사이의 유사성과 서로 다른 종류 사이의 궁합을 구분해 학습한다. 같은 카테고리로 바꾼 부정 예제를 사용해, 카테고리 구성만 맞추는 쉬운 문제와 미적 궁합을 구분하려 한다. 우리에게는 '유사도만으로 궁합을 결정하면 안 된다'는 근거다. 임의 색상 가중치나 모든 사람의 패션 정답을 제공하는 자료는 아니다.

### WACV 2023: OutfitTransformer

[원문 공개본](https://arxiv.org/html/2204.04812v2).

코디 전체 관계의 궁합 분류와, 부분 코디에 맞는 아이템을 검색하는 과제를 분리한다. 이미지 인코더도 학습하며 텍스트·검색 손실 등을 사용한다. 우리 동결 ResNet18+소형 헤드는 전체 재현이 아니다. 연구는 단일 정답 아이템 외에도 잘 맞는 대안이 있음을 지적하고 사람 비교를 추가한다. 따라서 FITB나 AUC만으로 실제 만족도를 대신할 수 없다. 이것이 후보 검색과 사람 평가를 별도로 준비해야 하는 이유다.

### CVPR Workshops 2021: 설명 가능한 궁합

[공식 초록](https://openaccess.thecvf.com/content/CVPR2021W/CVFAD/html/Kaicheng_Modeling_Fashion_Compatibility_With_Explanation_by_Using_Bidirectional_LSTM_CVPRW_2021_paper.html).

궁합과 설명을 함께 다루는 연구라는 서지·초록을 확인했다. 이번 조회에서는 공식 HTML/PDF 직접 열기가 403으로 제한됐다. 세부 실험 수치를 확인했다고 주장하지 않는다. 우리 시스템은 이 Bi-LSTM이나 그 설명 학습을 사용하지 않는다.

### AAAI 2024: Pair Fashion Explanation (PFE)

[원문](https://arxiv.org/html/2312.11554), [저자 코드](https://github.com/wangyu-ustc/PairFashionExplanation).

중요한 관계 특징 추출과 설명 생성을 나누고, 설명용 데이터로 언어모델을 학습·사람 평가한다. 데이터는 패션 글을 수집하고 ChatGPT로 추출·선별·재작성한 과정을 포함한다. 독립 전문가가 모든 사례를 직접 평가한 시각적 정답표는 아니다. 두 아이템의 텍스트 기반 관계 설명을 세 품목 사진 전체의 판정 정확도로 일반화하면 안 된다. 우리에게 유용한 것은 설명도 별도 감독·검증 대상이라는 설계 원칙이다.

### Polyvore의 실제 의미

[공식 데이터 카드](https://huggingface.co/datasets/mvasil/polyvore-outfits).

사용자가 구성한 코디와 상품 이미지·구성을 담는 대표 연구 데이터다. 우리 최신 Pool32는 정제된 데이터를 실제 학습했지만 웹과 분리돼 있다. 보고서의 AUC0.746/FITB42.23%는 재사용 테스트의 탐색 결과이며 서비스 합격률이 아니다. 부정 예제는 실제 모든 사람의 미적 반대 판단이 아니라 합성 교체 라벨이라는 한계가 있다. 데이터 카드의 원본 disjoint 설명과 우리 다운로드 파일 감사 결과도 구분해야 한다.

## 3. 추가로 발견한 후보 자료

### FashionStylist, 2026 사전공개 논문

[원문](https://arxiv.org/html/2604.09249), [저자 공개 저장소](https://github.com/recsys-benchmark/FashionStylist).

논문은 패션 전공 교수·대학원생 9명 팀의 주석 절차를 설명하고, 공개 저장소는 남성 300개를 포함한 1,000개 코디와 4,637개 아이템을 제공한다고 안내한다. 스타일·상황·전체 코디 설명을 다뤄 우리 평가 기준 후보로 적합하다. 사전공개 연구이며, 우리 사진 영역에서의 효과·해당 데이터의 사용 조건·독립 재현은 별도로 확인해야 한다. 지금 학습에 도입하지 않았다.

### VICTOR / Polyvore-MISFITs

[원문](https://arxiv.org/html/2207.13458).

전체 궁합 외에 코디 중 어떤 아이템이 맞지 않는지 검출하는 과제를 다룬다. '뭔가 이상함'에서 그치는 대신 교체할 품목을 찾는 방향의 근거로 참고할 만하다. 합성 부적합과 실제 사람의 판단은 같지 않으며 현재 모델을 적용한 것은 아니다.

### AesRec, 2026 사전공개 논문

[원문](https://arxiv.org/html/2602.03416).

미적 기준을 여러 차원으로 나누고 VLM 평가와 사람 평가를 비교한다. 다만 대규모 라벨에 VLM을 사용하며, 그 결과는 우리 Qwen3-VL-4B Q4_K_M의 보증이 아니다. 의류 성분·착용감·봉제 품질 등 사진에서 충분히 관찰할 수 없는 기준을 우리 점수표에 그대로 옮기지 않는다. 새 연구를 패션의 공인 규격이나 정답으로 인용하지 않는다.

### Qwen 공식 자료의 한계

[공식 모델 카드](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct).

범용 이미지·텍스트 모델이다. 조회한 모델 카드에서 우리 코디 과제의 전문성·전문가 일치율은 확인하지 못했다. 일반 시각 벤치마크와 빠른 CUDA 실행은 코디 판정의 전문성을 입증하지 않는다.

## 4. 시연 화면에 대한 진단

아래는 제공된 화면에서의 검토이며 전체 추천 성능의 통계적 판정은 아니다.

- 저지+데님+운동화처럼 무난하게 받아들일 조합도 있다. 무작위 수준이라고 단정하지 않는다.
- 같은 저지를 검정 티셔츠로 설명한다. 이미지 인식 단계와 등록 속성 연결을 점검해야 한다.
- 갈색 바지/흰 운동화의 대비를 부정 사유로 단정하는 설명은 설득력이 부족하다. 대비 자체는 긍정·부정 어느 쪽의 보편 규칙도 아니다. 신발 교체로 판단이 달라지는 것은 가능하므로 판정이 바뀌었다는 사실만으로 모순이라고 확정하지 않는다.
- 허리 높이·가죽/인조가죽·착용감 단정은 사진 근거가 충분한지 확인할 수 없다. 이 주장을 뺀 설명도 가능한지 검증한다.
- 약속·데이트는 너무 넓은 상황이다. 후드+반바지를 모두 부적합이라고 하드코딩할 수도 없고 모든 장소에 적합하다고 말할 수도 없다.
- 마지막 후보까지 추천 번호를 붙이는 것은 제품 표현 문제다. 낮은 품질을 감추는 방식과 실제 품질 향상을 구분한다.
- 세부 글자가 작은 마지막 캡처의 문장 전부를 읽었다고 간주하지 않는다. 정확한 사례별 판정에는 원문 JSON이 필요하다.

## 5. 개발 방향 제안

모델을 즉시 여러 개 더 붙이거나 Qwen을 버리기 전에, 현재 판정의 어디가 틀리는지 분리해야 한다. 아래는 구현 완료 항목이 아니라 제안이다.

### 먼저: 입력 사실 → 관계 판단 → 짧은 설명

등록 시 사용자 확인한 종류·색상은 출처와 함께 전달하고, 확인 안 된 AI 추정은 추정으로 구분한다. 사진과 속성이 충돌하면 무조건 속성을 믿지 말고 보류한다. 동일 옷을 코디마다 다르게 읽는 문제를 줄이는 후보 접근이다.

출력에는 관계 대상 item_id, 관찰 사실, 그 관계의 해석, 불확실성을 분리한다. 사용자가 보는 설명은 가장 중요한 관계 1~2개만 남긴다. 검증하지 않은 비율·소재·착용감은 설명에 쓰지 않는다. 여러 번 호출하는 것이 필수는 아니며, 우선 한 번의 구조화 응답으로 비교할 수 있다. 길고 자세한 문장을 품질로 평가하지 않는다.

### 후보 검색과 선별

현재 6개는 탐색용 배치로 취급한다. 좋은 후보가 없으면 0개도 허용한다. 부적합과 근거 부족을 구분하고, 둘 다 확신 있는 추천과 분리한다. 같은 등급 내부의 숫자 순위를 우열처럼 보여주지 않는다.

장기 후보는 작은 궁합 모델로 넓게 1차 평가하고 Qwen을 소수 후보의 관찰·상황·설명에 사용하는 방식이다. Pool32는 우선 같은 후보의 비공개 비교에 사용한다. 현재 성능만으로 실사용 1차 필터에 바로 넣으면 좋은 코디를 버릴 수 있다. 선택한 모델의 점수와 Qwen이 나중에 만든 이유가 같은 결정 근거라고 주장하지 않는다.

### 전문가 지식

논문에는 '색상40% + 스타일30%' 같은 보편적인 정답 공식이 없다. 전문가 주석 자료와 직접 평가를 통해 사례별 기준·허용되는 대안·보류해야 할 조건을 마련한다. 검색으로 참조 예시를 넣는 방법도 후보지만 단순히 글을 넣는다고 모델이 그 지식을 학습하거나 성능이 보장되는 것은 아니다. 문헌의 권위로 개별 출력 오류를 정당화하지 않는다.

## 6. 다음 실험: 비교할 내용을 먼저 고정

1. 고정 상의 하나에서 하의·신발을 한 개씩만 바꾸는 비교군을 만든다. 3개 하의×3개 신발이면 9개를 모두 비교할 수 있다. 이와 별도로 다른 의류 그룹의 보류 평가를 마련한다.
2. 사람은 AI 답을 보지 않고 적합/무난/부적합/판단 어려움을 기록한다. 취향, 시각적 조화, 상황을 구분한다. 패션 전공 평가자가 참여하면 전문성의 출처도 기록한다. 내가 만든 답을 전문가 정답이라고 부르지 않는다.
3. 현재 Qwen과 구조화 증거형 Qwen을 동일 후보·사진·모델 설정에서 비교한다. Polyvore 학습 모델은 별도 비교 축으로 둔다. 한 번에 모델·프롬프트·사진 크기를 모두 바꾸지 않는다.
4. 품목 순서와 컨택트 시트 배치를 바꿔 판정 변화를 기록한다. 순서를 바꿔도 반드시 완벽히 같아야 한다는 보장은 없지만 차이가 크면 사용자에게 순위를 믿게 해서는 안 된다.
5. 같은 옷의 사실 설명이 후보 간 유지되는지, 보이지 않는 속성 단정이 있는지 평가한다. 한 품목 교체가 설명과 판정에 합리적으로 반영되는지도 검토한다.
6. 추천만 남기는 정책은 사람 평가 기준의 나쁜 추천 비율과 함께 추천 제공률을 보고한다. 모든 것을 숨겨서 지표를 높이지 않는다. 설명 삭제로 오류율만 낮춘 경우에는 유용성도 함께 평가한다.
7. 지연은 업로드/전처리/평가/표시를 나눠 기록한다. 6개17초라는 시연값을 모든 사진과 모델 설정의 보장값으로 쓰지 않는다.

초기 개발 게이트 제안: 작은 고정 회귀 세트에서 명백한 비가시 속성 단정 0건, 부적합 후보가 추천에 섞인 사례 전수 검토, 평가자별 Top-3 수용도와 추천 제공률 동시 보고. 이는 프로젝트 목표이며 학계 공인 합격선이 아니다. 작은 세트에서 0건이어도 실제 서비스에서 오류가 없다는 뜻이 아니다.

## 7. 이번 작업의 범위

코드와 원문을 읽고 개발 판단 문서를 작성했다. 모델을 추가 학습하지 않았고, 프롬프트·후보 생성·제품 정책을 바꾸지 않았다. 소매 조건부 UI·연속 등록 버튼 요구도 별도 구현 항목으로 남아 있다. 다음 변경은 현재 화면을 기준선으로 보존한 비교 실험과 함께 진행해야 한다.
