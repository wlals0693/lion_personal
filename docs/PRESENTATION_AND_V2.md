# 11월 24일 개선판·노트북 발표 준비

## 이미 GPU 파일을 만들었다면: 화면만 업데이트

사진 목록·결과 목록만 나열하던 발표 화면을 단계별 사용자 흐름으로 수정했다. 기존 분석을 다시 실행할 필요 없다. 기존 캡처 폴더가 있는 데탑 `lion_personal`에서:

```powershell
git pull --ff-only
npm run refresh:presentation
```

최신 `presentation-output/*/presentation.json`을 자동으로 찾아 같은 폴더에 **wardrobe-demo-flow-생성시각.html**을 만든다. 기존 파일과 데이터는 보존한다. GPU·웹 서버가 꺼져 있어도 된다. 새 HTML만 노트북으로 옮긴다.

이미 HTML 하나만 노트북에 옮겼다면, 노트북의 최신 저장소에서:

```powershell
npm run refresh:presentation -- --input "기존 wardrobe-demo.html의 실제 경로"
```

기존 HTML에 내장된 JSON을 그대로 꺼내 새 화면에 넣는다. GPU 재계산·사진 재전송·결과 재작성은 하지 않는다.

### 발표에서 누를 순서와 말할 내용

1. HOME의 **사진 등록부터 시작**. 기존 발표용 기록이 있으면 확인 후 비운다. 실제 서비스 옷장은 건드리지 않는다.
2. **사진 선택하기** → 준비한 사진 한 장 → 분석 특징 확인 → **내 옷장에 저장**.
   말하기: “등록 부담을 줄이려고 사진에서 종류와 색상 같은 정보를 AI가 제안하도록 연결했습니다.”
3. 저장된 옷장 확인. **준비한 나머지 옷 불러오기**로 기존 분석 사진을 추가 → **이 옷들로 코디 찾기**.
   말하기: “등록한 옷이 옷장에 쌓이고, 이 옷들을 바탕으로 조합을 찾아봅니다.”
4. 외출 상황 선택 → **이 상황의 코디 확인하기** → **이 코디 선택하기**.
   말하기: “조화와 상황 적합성을 나눠 판단하고, 근거가 부족한 후보는 보류합니다. 현재는 전문적인 판단과 설명의 사실성을 검증하는 단계입니다.”
5. 상세 → **오늘 입을래요** → 착용 예정 기록 → **HOME에서 결과 확인**.
   말하기: “선택한 코디를 입을 예정으로 남깁니다. 실제 착용 기록과 구분하면서 내 옷을 계속 활용하는 흐름까지 연결했습니다.”

상단 4단계 표시로 현재 위치를 보여준다. 발표 파일의 사진 선택은 준비된 사진 선택이며 새 사진 업로드·실시간 분석이라고 설명하지 않는다. 원래 서비스에서는 분석 결과를 수정할 수 있지만 이 발표 파일은 기록된 결과를 보존한다. 추천 설명의 사실 오류는 화면 구성 변경으로 해결되지 않으며 기존 실제 결과를 그대로 재생한다.

## 데탑에서 해야 할 마지막 실행

기존 GPU 모델·가상환경은 재사용한다. 실행 중인 이전 GPU 서버는 자기 실행 터미널에서 Ctrl+C로 종료한 후 최신 코드로 다시 실행해야 v2가 반영된다. 다른 사용자의 프로세스를 강제로 종료하지 않는다.

`lion_personal` 폴더에서:

```powershell
git status --short
git pull --ff-only
npm ci
npm run demo
```

Ready와 GPU 준비 완료를 기다린 뒤, 새 터미널을 같은 폴더에서 열고:

```powershell
npm run capture:presentation -- --photos "C:\사진폴더\demo_today"
```

사진 폴더는 top / bottom / shoes(또는 shoe) 구조를 사용한다. 각 3장 권장, 장당 3MB 이하 JPG/PNG/WebP. 기존 전달 ZIP의 정리된 사진 9장을 사용할 수 있다. `C:\사진폴더\demo_today`는 실제 압축을 푼 위치로 바꾼다.

정상 완료하면 콘솔에 **wardrobe-demo.html의 절대 경로**가 출력된다. 기본 출력은 `presentation-output/생성시각/`이며 기존 폴더를 덮지 않는다. 실패하면 가짜 결과로 채우지 않는다. 모든 사진의 종류 분류가 맞는지, 실제 결과가 발표할 만한지는 반드시 데탑에서 먼저 열어 확인한다.

## 노트북에서는

생성된 **wardrobe-demo.html 한 파일**을 노트북으로 옮겨 Chrome 또는 Edge로 더블클릭한다. npm·인터넷·GPU·모델 설치가 필요 없다. 파일 안에 실제 사진과 실제 응답이 들어 있다. 코드나 모델을 다시 실행하지 않는다.

- 옷장: 준비한 사진을 고르고 사전 분석 결과를 확인해 하나씩 등록한다.
- 코디: 등록한 옷으로 만들 수 있는 사전 평가 사례만 표시한다.
- 상황: 일상·산책 / 약속·데이트 / 한 상의 고정의 준비된 사례를 선택한다.
- 선택한 코디: 오늘 입을래요 → 입을 예정 기록 → HOME.
- 등록·기록은 로컬 브라우저에 저장한다. 브라우저 파일 저장이 제한되면 안내 메시지를 표시한다.
- 새 사진 분석, 새로운 조합 실시간 평가, 분석 정보 수정은 실시간 서비스에서만 가능하다. 오프라인 파일에서 실행한 것처럼 표현하지 않는다.
- 상단에 **GPU 사전 분석 결과 재생**을 계속 표시한다. 진행 현황에서 모델·생성 시각·미완료 항목을 설명한다.

파일은 사진을 포함하므로 Git에 넣지 않았다. 지금은 별도 외부 배포를 하지 않는다. 이 방식은 발표 현장의 네트워크와 원격 데탑에 의존하지 않는 로컬 배포 형태다. 새 사진을 현장에서 실시간 처리하려면 GPU 서버를 계속 켜두고 별도의 인증된 원격 연결을 구성해야 하며, 이번 작업에서는 외부 공개/포트 개방을 하지 않았다.

## 개선한 것

### 실제 웹 UX

- 하의·신발에서는 소매·목 형태 입력과 관련 상세 표시를 숨긴다.
- 의류 상세에 다른 옷 등록하기 추가.
- 코디 화면은 핵심 설명과 이미지 중심으로 정리하고 긴 판단 범위는 접는다.
- 추천 가능한 후보만 본문에 표시. 보류·제외는 접힌 별도 영역. 0개 추천도 허용.
- 같은 등급의 카드 번호를 미세한 우열처럼 설명하지 않는다.

### 코디 평가 v2

- 등록 종류·색상·카테고리를 사진 번호에 연결. reviewed는 사용자가 등록 폼을 수락했다는 뜻이며 전문가 정답이 아니다. 캡처 도구의 자동 분석 값은 reviewed=false로 전송한다.
- 관찰 evidence / 관계 해석 observation / 관련 itemIds 분리. 1~2개 관계만 출력.
- recommend / hold / reject 구분. 상황 불명확, 시각적 근거 부족은 보류.
- 사진 밖 아이템 인용이나 일부 명백한 비가시 속성 단정은 보류하는 보수적 검사를 추가. 정규식은 의미 검증이나 환각 완전 검출이 아니다.
- 학습 모델을 새로 추가하거나 Qwen을 fine-tuning하지 않았다. 논문에서 확인한 관계 평가·설명 분리 원칙을 적용한 실험판이다.
- v1 코드는 별도 파일로 보존. 두 버전은 같은 사진·컨택트 시트·후보를 사용한다. 프롬프트·schema·출력 상한(512→650)은 다르므로 그 전체 변경의 비교다.

## 결과 파일

| 파일 | 내용 |
|---|---|
| wardrobe-demo.html | 인터넷 없는 발표용 단일 파일 |
| presentation.json | 원본 사진·분석 응답·개선판 코디·시간 |
| comparison.json | 일상 후보 6개의 기존판·개선판 결과 |
| README.txt | 옮기는 방법 |

추출 시 실제 사진 9회 분석, 기존판 1배치, 개선판 3배치(각 최대 6개)를 순차 실행한다. 시간은 실제 기기와 출력에 따라 달라지며 캡처 과정의 실측값을 저장한다. `gpu-capture`는 실행 경로 표시이며 별도 CUDA 하드웨어 로그를 새로 감사했다는 뜻은 아니다.

## 검증과 남은 한계

노트북: TypeScript 검사·프로덕션 빌드·JS 테스트 20개·Python 경계 테스트 4개 통과. 오프라인 file:// Chrome에서 등록·추천 선별·예정 기록·새로고침·모바일 가로 넘침·외부 네트워크 요청 없음 확인. 캡처 명령은 로컬 테스트 서버로 사진 9장/버전별 프로토콜/동일 후보/HTML 내장을 검증했다.

위 화면·생성기 검사는 **테스트 응답**으로 실행했다. 노트북에서는 실제 CUDA 추론, v2의 사람 평가 일치율, 출력 길이 안정성, 추론 지연 개선을 측정하지 않았다. 실제로 더 좋은 추천이 나왔다는 결론은 아직 내리지 않는다. 데탑 comparison.json을 보고 사실 오류·판정 일관성·불필요한 보류·추천 제공률을 함께 검토한다.

발표 설명 예시: “사진 분석부터 옷장·코디·착용 예정 기록까지 연결했습니다. GPU에서는 실시간 분석하고, 오늘은 그 실제 분석 결과를 노트북에서 재생합니다. 현재는 전문가와의 판단 일치와 설명의 사실성을 개선하는 단계입니다.”
