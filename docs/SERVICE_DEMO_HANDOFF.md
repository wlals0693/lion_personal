## 사진

노트북에서 제공하는 `demo_today_ready.zip`을 데탑에 옮겨 직접 압축 해제한다. `demo_today/top` 3장, `bottom` 3장, `shoes` 3장. 실제 사진은 Git에 넣지 않았다. 원본 보존 후 EXIF 보정·첫 프레임·RGB JPEG 복사본을 만들었다. 내용 분석 정답을 미리 넣은 것이 아니다. WebP의 잘못된 jpg 확장자와 MPO 형식을 정리한 복사본이다.

## 수동 시연

1. 시작 화면에서 GPU 연결 확인. 준비 상태일 뿐 정확도 검증은 아니다.
2. 처음이라면 체험 로그인 → 선호 설정 또는 건너뛰기 → **내 옷 사진으로 시작**.
3. 기존 예시 옷장이 있으면 시작 화면의 **예시 옷만 정리**. 명시적 확인 후 예시 옷·연결된 기록·좋아요만 제거하고 직접 등록한 옷은 유지한다.
4. 사진을 한 장씩 등록. 이름·종류·카테고리를 확인 후 저장. 등록 상세에서 옷장으로 돌아가 추가하거나 `/wardrobe/new`로 이동해 총 9장 등록.
5. 옷 하나의 상세 → **이 옷으로 코디 추천** → 상황 선택 → **AI로 코디 추천받기**. 후보 최대 6개를 실제 Qwen으로 평가하며 수십 초 걸릴 수 있다.
6. 코디 상세에서 같은 AI 이유 확인 → **오늘 입을래요** → **기록 저장**. 상태는 입을 예정이며 자동으로 실제 착용 확정하지 않는다.
7. HOME에서 평가된 코디와 입을 예정 기록 확인. 새로고침 후에도 유지한다.
8. 구매분석은 별도 체험 흐름이다. 화면에 명시된 예시 데이터이며 실제 구매 활용도 모델이라고 설명하지 않는다.

## 변경 내용

- `/demo/start`: GPU 상태·현재 등록 수·시연 동선. `npm run demo`도 이 주소를 안내한다.
- `/api/gpu/health`: Next 서버에서 gateway 준비 상태 확인. 연결 실패는 503.
- 평가된 코디를 브라우저 저장소에 보존해 상세/새로고침/HOME에 연결.
- 평가에 쓰인 옷을 편집·삭제·추천 제외하면 이전 평가를 무효화. 새 옷을 추가하는 것만으로 다른 코디 평가를 지우지 않는다.
- HOME과 사이드바에서 실제 연결 범위를 정확히 표기.
- 앞서 만든 사람 평가 준비 도구는 `/demo/evaluation`에 별도 유지.

## 검증 범위

노트북에서 JS 회귀 테스트 19개와 프로덕션 빌드 통과. 실제 사진 9장으로 Chrome에서 로그인/온보딩/등록/고정 코디/상세/새로고침/예정 기록/HOME을 확인했다. 모바일 390px 가로 넘침과 pageerror 없음 확인. 이 검사에서는 AI API 응답을 **테스트용 응답으로 대체**했다. 실제 CUDA 실행·새 사진의 분류 정확도·코디 품질·추론 시간은 노트북에서 검증하지 않았다.

## 데탑 실제 GPU 자동 검사 (Chrome 설치 필요)

`npm run demo`를 켠 상태에서 별도 터미널:

```powershell
$env:WARDROBE_WEB_URL = 'http://127.0.0.1:3000'
$env:WARDROBE_DEMO_PHOTOS = 'C:\사진을푼위치\demo_today'
node scripts/test-service-flow.mjs --gpu
```

`--gpu`에서는 테스트 응답을 사용하지 않는다. 실제 사진 9장을 전송하고 실제 gateway를 사용한다. 새 브라우저 컨텍스트를 사용해 기존 사용자의 옷장은 건드리지 않는다. 결과는 Git 제외 `test-results/service-flow-gpu.json`이며 실행 성공과 시각적 정답률은 별개다. AI가 사진을 다른 카테고리로 분류해 완성 코디가 안 만들어지면 자동 검사가 멈출 수 있으므로 수동으로 분석 결과를 확인한다. 결과 보고서에 성공/실패와 수정 필요 항목을 남긴다.

노트북 프론트 검사:

```powershell
node scripts/test-service-flow.mjs
```

기본 사진 경로는 로컬 `test-results/demo_today_ready`다. 테스트에서 쓰는 파일명→종류 매핑은 테스트 응답 생성용이며 실제 앱/실제 GPU 추론에는 적용하지 않는다.

실제/테스트 응답 모드 모두 사진과 스크린샷은 test-results에만 저장한다. API 응답 테스트 성공을 모델 정확도로 발표하지 않는다. 인증·날씨·구매분석은 mock, 실제 서버 DB·개인화·Pool32 연결·외부 배포는 이번 범위에 없다.
