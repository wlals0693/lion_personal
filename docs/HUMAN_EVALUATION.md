# 코디 사람 평가 준비 도구

`npm ci` → `npm run dev` → http://localhost:3000/demo/evaluation

GPU·로그인 없이 사용한다. 기존 옷장 저장소와 다른 키에 저장한다.

1. 새 사진을 상의/하의/신발로 추가한다. 각 5장 권장, 전체 30장 이하, 장당 2MB 이하 JPG/PNG/WebP. 원본 파일명은 실험 입력에 넣지 않는다.
2. 평가자 별칭·역할과 공통 외출 상황을 정한다. 최대 24개 코디를 결정론적으로 전체 조합에 분산해 구성한다. 모든 조합을 검증하는 방식이 아니며 모든 크기의 목록에서 모든 옷의 등장을 보장하지 않는다.
3. 모델 결과를 보지 않고 시각적 조화(좋음/무난/어색함), 상황 적합성, 이유를 각각 입력한다. 이것은 평가자의 판단이며 전문가 정답이라고 간주하지 않는다.
4. 모두 작성하면 확정한다. 확정 후 화면에서 수정할 수 없다. 개발자 도구 변경까지 막는 변조 방지 시스템은 아니다.
5. `experiment.json`은 사진 원본(base64)·SHA256·아이템 ID·코디·상황만 포함한다. `human.json`은 사람 평가다. 모델에 사람 평가를 전달하지 않는다.
6. `backup.json`은 사진과 사람 평가를 함께 보관한다. 다른 브라우저에서 백업 불러오기로 복원할 수 있다. 여러 평가자는 같은 후보의 평가 전 백업을 공유하고, 각자 별칭과 평가를 기록한다.

사진은 서버로 보내지 않는다. 브라우저 IndexedDB에 저장한다. 저장 공간은 제한적이므로 저장 실패 메시지가 나오면 즉시 백업을 내려받는다. 많은 사진은 백업 파일로 보존하고 페이지를 떠나기 전에 확인한다. 새 사진 세트라는 표시는 독립성을 자동 보증하지 않는다. 기존 사진은 연습용으로 표시한다.

## 데탑 전달

코드는 Git, 사진이 포함된 experiment/backup 파일은 별도로 전달한다. 실험 파일은 개인 사진을 포함하므로 저장소에 자동으로 추가하지 않는다.

```powershell
python scripts/prepare_human_experiment.py --input "C:\path\set-experiment.json" --out training/runs/human_eval_01
```

이 명령은 사진 바이트의 SHA256을 검사하고 새 경로에 `images/`와 `manifest.json`을 만든다. 기존 경로를 덮어쓰지 않는다. 모델 추론은 실행하지 않는다.

## 이번 구현 범위와 다음 연결

이번 변경은 블라인드 사람 평가 수집과 동일 입력 전달까지다. Qwen/Logistic/Pool32 일괄 실행 및 결과 재수입·통계 비교는 아직 연결하지 않았다. 특히 현재 `predict_compatibility.py`의 기본은 기존 Transformer라서 Pool32라고 부르면 안 된다. 데탑에서 체크포인트·특징 인코더·종류 매핑을 확인한 뒤 실행 어댑터를 추가해야 한다. 본 화면에서 모델 성능 숫자를 생성하지 않는다.

## 검증

2026-11-20: JS 테스트 19개, 타입 검사, 프로덕션 빌드 통과. 실제 Chrome에서 24개 평가·IndexedDB 새로고침 복원·확정·사람 답 없는 내보내기·390px 가로 넘침 및 콘솔 오류 없음 확인. 내보낸 사진 12장의 SHA256 검증 및 데탑 폴더 생성도 확인했다. GPU 모델은 실행하지 않았다.

Chrome이 설치된 환경에서 실행 중인 웹을 대상으로:

```powershell
$env:WARDROBE_WEB_URL = 'http://localhost:3000'
node scripts/test-human-evaluation.mjs
```

격리된 브라우저의 연습 데이터로 검사한다. 결과 사진과 파일은 Git 제외 `test-results/`에만 저장한다.
