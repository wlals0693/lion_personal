# 옷의 여유 — AI 디지털 옷장 프로토타입

Next.js App Router · React · TypeScript · Tailwind CSS 기반의 모바일 우선 옷장입니다. 사진 등록의 이름·종류·소매·색상·스타일·패턴·목 형태·원단 추정을 로컬 Qwen3-VL 4B GPU 모델에 연결했습니다. 인증·코디·구매분석·날씨는 체험용입니다.

## 로컬 실행

### AI 코디 데모 바로 확인

```powershell
npm run demo
```

`GPU gateway ready`와 웹 `Ready` 표시 후 **http://127.0.0.1:3000/demo/outfits** 에서 ‘AI로 코디 추천받기’를 누르세요. 전달받은 사진 60장 전체와 하의·신발 예시 8벌을 합친 **68개 등록 항목**으로 실제 GPU 평가를 확인합니다. 전체 목록 검색·분류·특정 옷 고정·추천 제외와 ‘다른 후보 만들기’를 지원합니다. 데모가 내 옷장 데이터를 바꾸지는 않습니다. 내 옷장 코디 메뉴에서도 같은 AI 평가를 사용할 수 있습니다. 기존 `npm run gpu`·웹 서버와 포트가 같으므로 중복 실행하지 않습니다. 종료는 Ctrl+C입니다.

68개 항목을 연결한 검증에서 후보 6개 평가에 약 16.3초가 걸렸습니다. 조화 판단은 전문가 평가와 아직 검증하지 않은 초기 AI 의견입니다. 범용성·개인화는 이번 범위에 포함되지 않습니다. [60장 자료 연결 검증](docs/OUTFIT_DEMO_CATALOG_REPORT.md)과 [초기 개발 보고서](docs/OUTFIT_AI_DEMO_REPORT.md)를 확인하세요.

Node.js 22 이상 권장. 현재 개발 환경은 Node.js 24입니다.

```powershell
npm ci
npm run dev
```

브라우저에서 http://localhost:3000 을 엽니다. 개발 서버 종료는 해당 터미널에서 Ctrl+C입니다. 프로젝트 폴더에서 실행해야 합니다.

### 로컬 GPU 사진 등록

이 체크아웃 옆 `../wardrobe-desktop-handoff`의 검증된 모델·비전 프로젝터·llama.cpp CUDA 실행파일과 Pillow가 설치된 `.venv`를 사용합니다. GPU를 사용하는 게임을 종료하고, 별도 터미널에서 먼저 실행합니다.

```powershell
npm run gpu
```

`GPU gateway ready`가 표시되면 다른 터미널에서 `npm run dev`를 실행합니다. 가입 없이 데모 체험·온보딩 후 `/wardrobe/new`에서 사진을 올리면 이름·종류·소매·색상·스타일·패턴·목 형태·원단 추정이 자동 입력됩니다. 직접 수정한 값도 저장·새로고침 후 유지됩니다. 사진은 메모리에서 처리하고 분석 서버에 저장하지 않습니다. 옷장 저장 버튼을 누르면 기존 방식대로 브라우저 localStorage에 사진과 의류 정보를 저장합니다.

GPU 서버는 `127.0.0.1:8092`, 모델 서버는 `127.0.0.1:8091`에만 바인딩합니다. 기본 모델 경로는 인접 폴더이며 `WARDROBE_MODEL_ROOT`, Python은 `WARDROBE_PYTHON`으로 바꿀 수 있습니다. 웹 서버의 GPU 주소는 `.env.local`에 `.env.example`을 복사해 설정할 수 있습니다. 모델 서비스는 `WARDROBE_GPU_PORT`·`WARDROBE_LLAMA_PORT` 환경변수도 지원합니다. 각 터미널에서 Ctrl+C로 종료합니다.

원본 파일을 GPU 서비스에서 EXIF 보정·RGB 변환·최대 768px LANCZOS 전처리합니다. Q4_K_M·F16 프로젝터·temperature=0·seed=42·배치 128·CUDA0 조건이며 모델을 메모리에 유지합니다. 추가 속성을 위해 `scripts/registration_prompt.txt`의 전용 프롬프트와 최대 384토큰을 사용하므로 앞선 60장 실험과 프롬프트·토큰 한도가 다릅니다. 사진 픽셀과 공통 프롬프트만 모델에 전달합니다. 이름은 예측 색상·종류를 조합합니다. 스타일은 주관적 제안이고 원단은 시각적 느낌이며 실제 섬유 성분을 확정하지 않습니다. 불명확한 값은 모르겠어요 또는 빈칸으로 두고 확인 필요 항목을 표시합니다. 서버 연결 실패 시 가짜 결과로 대체하지 않고 오류·재시도를 제공합니다. 제공된 예시 이미지를 선택한 경우만 기존 체험용 응답을 사용합니다.

화면의 시간은 업로드 버튼 클릭부터 종류·소매 입력란이 렌더링된 후 두 번째 animation frame까지입니다. 파일 선택창에서 사용자가 머무는 시간도 포함하고, `사진 선택 후` 시간도 별도로 표시합니다. 모델 준비 시간은 상주 서버 시작 때 발생하므로 이 값에 포함되지 않습니다. 브라우저 `performance`에 `wardrobe-upload-to-visible` 측정값도 남깁니다.

실제 브라우저 검증은 두 서버가 실행된 프로덕션 빌드에서 진행합니다.

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH='.playwright'
npx playwright install chromium --only-shell
npm run build
npm start -- --hostname 127.0.0.1
# 별도 터미널
npm run test:gpu-web
```

이 검증은 로컬 실제 사진 5장으로 자동 입력·수정·저장·새로고침·오류/재시도·모바일 화면을 확인합니다. 시간 원문과 스크린샷은 git에서 제외된 `test-results/`에 저장됩니다. 파일 선택은 자동화하므로 사용자가 파일을 찾는 시간은 재현하지 않습니다.

Windows에서 Turbopack의 CSS 처리 하위 프로세스 오류를 확인하여 `dev`와 `build`는 Next.js가 지원하는 Webpack 옵션으로 설정했습니다. Vite/Vinext/Cloudflare 전용 실행기가 아닙니다.

```powershell
npm run typecheck
npm test
npm run build
npm start
```

## 체험 순서

1. **가입 없이 데모 체험** → 닉네임/스타일/색상 → **예시 옷 12벌로 먼저 체험**.
2. 옷장 → 옷 등록 → 자신의 사진을 선택하거나 제공된 예시 사진 선택.
3. 특징 후보 확인 → 이름·종류·색상·스타일 확인/수정 → 저장.
4. 저장한 의류 상세에서 **이 옷으로 코디 추천** → 코디 상세 → 좋아요 → **오늘 입을래요**.
5. 날짜별 착용 기록에 **입을 예정**으로 저장된 것을 확인. 실제 입은 것으로 남기려면 사용자가 명시적으로 종류를 바꿔 저장.
6. 구매분석 → 상품 사진과 정보 → 분석 → 유사 의류·조합·추가 조합의 예시 → HOME.

초기 옷 등록에서 **내 옷 사진으로 시작** 또는 **건너뛰기**를 선택하면 빈 옷장으로 시작합니다. 빈 상태에서는 직접 상의·하의·신발 또는 원피스·신발을 등록해야 완성된 코디가 생깁니다.

## Mock과 실제 동작의 구분

- **실제 프론트 동작:** 파일 읽기·축소·미리보기, 의류 CRUD, 검색, 고정 의류 유지, 제외 반영, 좋아요, 기록 CRUD, 달력, 설정, 브라우저 저장·복원.
- **사진 특징 분석:** 직접 업로드한 사진은 로컬 Qwen3-VL 4B CUDA 모델로 종류·소매·색상·스타일·패턴·목 형태·원단 느낌을 예측하고 이름을 자동 생성합니다. 제공된 예시 사진은 체험용 응답입니다. 정답 확률/신뢰도를 만들지 않습니다.
- **코디 추천:** 카테고리로 만든 후보는 평가 전으로 표시합니다. ‘AI로 코디 추천받기’를 누르면 최대 6개를 로컬 GPU가 사진으로 평가해 전체 조화와 상황 적합성을 나눠 표시하고 정렬합니다. 개인화는 없으며 판단 정확도는 아직 사람의 평가로 검증하지 않았습니다. 다른 코디로 넘긴 행동은 싫어요로 저장하지 않습니다.
- **유사 의류:** 같은 카테고리 의류를 비교 예시로 표시합니다. 실제 이미지 벡터 검색이 아닙니다.
- **구매 Utility:** 최대 6개 조합에 대체/추가의 예시 상태를 부여하는 UI fixture입니다. 색상·스타일 일치 여부를 단순 예시 생성에 사용하며 검증된 대체성 기준이 아닙니다. 화면에 **예시 데이터**를 표시합니다. 실제 전체 후보 집합 Utility나 구매 권장 점수를 구현했다고 해석하면 안 됩니다.
- **착용 기록:** ‘오늘 입을래요’는 `planned`입니다. `recorded`는 사용자가 직접 남긴 기록이며 실제 착용을 자동으로 확인했다는 의미가 아닙니다. 기록이 없다는 이유로 추천에서 제거하지 않습니다.
- **날씨/인증:** 날씨 숫자는 고정 예시, 지역명만 설정값을 사용합니다. 계정 생성/메일 발송/실제 로그인이 없고 비밀번호를 저장·전송하지 않습니다.

## 데이터와 API 연결 위치

```text
app/                  App Router 진입점, 전역 스타일, 오류 화면
components/           화면 UI와 사용자 동작
  store.tsx           공통 상태·저장 성공 처리·알림
lib/
  types.ts            의류/프로필/코디/기록/분석 응답 타입
  seed.ts             예시 의류의 유일한 원본 데이터
  repository.ts       저장소 어댑터 (현재 localStorage)
  mock-api.ts         비동기 인증/분석/추천 인터페이스, 로딩/오류
  wardrobe-logic.ts   검증 가능한 Mock 조합·Utility 생성
tests/                로직·저장·컴포넌트 통합 테스트
public/clothes/       기존 제공된 직접 촬영 의류 사진 12장
```

`lib/mock-api.ts`의 `WardrobeApi`를 FastAPI 요청 어댑터로, `lib/repository.ts`의 `WardrobeRepository`를 Supabase 또는 서버 저장 어댑터로 교체할 수 있도록 UI의 직접 저장소 접근을 분리했습니다. 현재 저장소 인터페이스는 동기식이므로 실제 비동기 저장 연결 시 Provider의 저장 완료·오류 처리를 함께 비동기로 바꿉니다.

추후 실제 API 연결 대상은 인증, 사용자별 의류 CRUD와 이미지 스토리지, 특징 분석, 유사 검색, 추천/호환도, 좋아요·착용 기록, Utility, 날씨입니다. 아직 이 API나 AWS 자원은 만들지 않았습니다.

기획한 최종 AWS 구성으로 옮길 때는 API 주소·인증·이미지 저장 어댑터를 연결하고 프론트 배포 방식을 별도로 정하면 됩니다. 현재 프론트가 Vercel 전용 서버 기능이나 Cloudflare 저장소에 의존하지는 않습니다.

## 저장과 상태 체험

브라우저의 `ai-wardrobe-prototype:v1` 키에 의류·사진·설정·좋아요·기록을 저장합니다. 다른 기기/브라우저와 동기화되지 않으며 실제 계정별 데이터 격리도 없습니다. Mock 로그인은 보안 수단이 아닙니다.

사진은 최대 12MB JPG/PNG/WebP, 최대 변 900px JPEG로 줄여 브라우저에 저장합니다. 용량 부족 시 저장 실패를 알리고 성공한 것으로 표시하지 않습니다. 예시 사진은 축소하고 메타데이터를 제외한 복사본이며 원본 사진은 수정하지 않았습니다.

- **Empty:** 빈 옷장, 필터 결과 없음, 추천 조합 부족, 비교 의류 없음, 기록 없음.
- **Loading:** 초기 저장소 읽기, 로그인, 특징 분석, 코디 추천, 구매 분석.
- **Error:** 사진 형식/크기/디코딩, API 실패·재시도, 저장 용량·데이터 손상, 잘못된 주소/삭제된 의류.
- 마이페이지 → **체험 동작 확인 → 다음 요청 실패 체험**으로 다음 Mock API 요청의 오류·재시도를 확인할 수 있습니다.
- 마이페이지 → **체험 데이터 초기화**로 시작 상태로 돌아갑니다. 이 브라우저의 데이터만 지웁니다.

## Vercel에 올리기

GitHub 저장소의 루트가 이 프론트 프로젝트입니다.

1. Vercel에서 `wlals0693/lion_personal` Import.
2. Framework Preset: **Next.js**.
3. Root Directory: **기본값 `./`**. 저장소 안에 `wardrobe-web`이 한 번 더 들어가지 않습니다.
4. Install: `npm ci`, Build: `npm run build`. Output Directory는 Next.js 기본값.
5. 로컬 GPU 연결은 위 실행 방법을 사용합니다. 웹만 배포해도 사용자 PC의 GPU 서버에는 연결되지 않습니다.

## 검증 범위

`npm run typecheck`, `npm run build`, `npm test`를 통과했습니다. 기존 `npm test` 12개는 로직과 가상 DOM에서의 컴포넌트/공통 상태 흐름을 확인합니다.

사진 등록은 추가로 `npm run test:gpu-web`에서 실제 headless Chromium·Next.js 프로덕션 서버·로컬 GPU 모델을 연결해 검증했습니다. Windows의 자동화 파이프 시작 문제를 피하도록 테스트 스크립트가 숨김 브라우저를 실행하고 로컬 TCP CDP로 연결합니다. 5장 자동 입력·수정·저장·새로고침·오류/재시도·390px 모바일 화면을 확인했습니다. 검증 결과와 측정 조건은 [GPU 사진 등록 보고서](docs/GPU_REGISTRATION_LOCAL_REPORT.md)를 확인하세요. 전체 앱의 뒤로 가기·실물 모바일 기기·키보드 접근성 전체를 검증했다는 의미는 아닙니다.

추가 등록 속성의 실제 GPU 검증과 측정값은 [속성 확장 보고서](docs/GPU_REGISTRATION_ATTRIBUTES_REPORT.md)를 확인하세요. 미확인·잘못된 모델 속성 정규화 검증은 `../wardrobe-desktop-handoff/.venv/Scripts/python.exe scripts/test_gpu_attributes.py`로 실행합니다.
